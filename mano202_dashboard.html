How Offline Buffering Works
1. Every ~30s poll, each meter reading is POSTed to Supabase immediately.
2. If WiFi/Supabase is down, that reading is written as one JSON line to /queue.jsonl on the SD card instead of being lost.
3. Each queued reading is timestamped from NTP when online, or the onboard DS3231 RTC when offline — so shift/energy totals stay accurate even during a multi-hour outage.
4. Once WiFi + Supabase are reachable again, the device re-sends queued rows in batches every ~15s and trims them off the card as they succeed.
📱 Hosting this dashboard for one-tap updates
Put mano202_dashboard.html, manifest.json, sw.js and version.json together at one URL — a free static host (GitHub Pages/Netlify) or your office PC's LAN web server both work. On each phone: open that URL in Chrome → menu → "Add to Home Screen". From then on it behaves like an installed app icon, but editing the hosted file instantly updates every phone (see the OTA/WiFi page for the "Reload now" banner). Bump the version number in version.json and the app-version meta tag together whenever you publish a change.
Meter Setup
Admin-only · choose how many meters (M1…Mn) each production panel actually has wired
Every dashboard page, PDF report, Modbus editor and terminal command reads this count — set it once here instead of a fixed M1-M5. Range: 1 to 8 meters per panel. Applying a change also pushes the active meter-ID list to the device so unused Modbus slots are no longer polled.
Shift Timings
Admin-only · define the shift slots used for shift-kWh totals, the PDF report, and the dashboard shift indicator
⚠ Shifts must not overlap and should cover the full 24h if you want continuous shift-kWh accounting. Times are 24h local (IST); an overnight shift (e.g. 22:00→06:00) is supported.
